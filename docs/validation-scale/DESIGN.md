# Versioned scale design

Use the existing validator protocol and immutable engines for the next largest independently supportable cohort: all51 remaining supplied-mathematics profiles. Preserve the original28 adapters and all shipped v1 packets. This is private witnessed engineering, not canonical approval.

Two compatibility issues govern the implementation. First, the v1 capture selected files using a live glob; adding a new revision changes that capture even when old dependency bytes are unchanged. Freeze each revision’s exact membership and authenticate its SHA preimage, retaining original per-file hashes. The original v1 has433 captured files and the new v2 has439; both retain fixed memberships under future additions. Second, new raw binary64 helper witnesses need an explicit numeric error policy, so keep v1's strict comparator unchanged and introduce a separate revision2 comparator with capped, declared primary-scalar tolerance. Both zeros, nulls, signs and all non-primary fields stay exact.

The alternatives were rewriting historical captures/readers or normalizing actual engine outputs. Both would undermine immutable evidence. Instead, use new revision2 adapters, source capture, packets and reader dispatch, reusing the v1 reader directly. No old engine or mathematical helper changes. An additive review route exposes79 adapters without changing the shipped28-adapter route or tests. Original v1 history is read separately and copied only through explicit Save; no silent migration or overwrite.

The new540-row evidence overlay preserves prior unextended records. It records exact witness checks, absolute tolerances and partial/blocked applicability. #528's gross-MET formula remains explicitly caller-supplied and clinically unapproved. No source/provider/jurisdiction/clinical decision is inferred from successful arithmetic.

Bounded CI adds the new mandatory source/evidence/browser acceptance after the existing build-job steps; original v1 steps and both-job fail-closed aggregate remain exact. The preservation guard requires the original4 steps, prior2 additions and exact new mandatory step. Timeouts, triggers, permissions and concurrency remain unchanged.

Future revisions must preserve these source memberships, packets and reader dispatch. Full authenticated account and canonical UI acceptance remain separate requirements. RELEASE HOLD remains active.
