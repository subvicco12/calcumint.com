# Final-two guarded SQL model

These are unactivated successor proposals for #368 `technology.ip-subnet@1` and #376 `technology.screen-ppi@1`. They extend the retained native18 allowlist to20 and private sharing13 to15. The other tuples, including Website Bandwidth@2, remain unchanged. No active migrations or prior held packages were edited.

Both directions require the reviewed local postgres operator, READ COMMITTED, table locks and exact scoped metadata preimages. Native metadata includes function definitions/configuration/ACL, table and column ACL, RLS/policies, constraints, indexes and trigger state. Sharing also binds the auth.uid helper and individual predecessor function definitions. Original source hashes and immutable artifacts remain retained. Changed privileges, source, owners, triggers, constraints, indexes, policies and helper definitions refuse adoption. Reverse refuses durable new-profile rows; it never deletes audit or calculation data. External writers and authentic target compatibility still require separate reconciliation before any adoption.

Sharing private3 preserves the unchanged six-key service payload and all13 prior valid profile writes. It adds exactly two profiles and updates the capability/RLS revision together. The application must continue allowing private2 for its old13 scope before adoption and must require private3 for the new two; the SQL payload itself contains no revision field. No old request payload, ID or recorded snapshot is rewritten. A pre-upgrade binary that insists on capability private2 has not been established compatible with private3. Adoption therefore requires separately approved quiesced deployment and reconciliation of all participating application/privileged writers; this remains an operator/deployment BLOCKER, not a reason to bypass a gate.

The isolated SQL fixtures use pinned PostgreSQL17.6, GoTrue and PostgREST, with generated nonproduction identities on a random internal Docker network and no exposed ports or production connection fallback. Native assertions call SQL under explicit roles; they are not HTTP authentication acceptance. Sharing exercises genuine local GoTrue sessions and PostgREST, service-only writes, member/viewer/foreign isolation, revocation, malformed/unsupported profiles and concurrent duplicate/audit behavior.

Native lower-publication results and SQL snapshot input/output are explicitly synthetic. SQL storage trusts the verified server for mathematics. These tests prove scoped model behavior, not calculator mathematics, full hosted-schema equivalence, qualified review, certification or publication eligibility. Actual-engine and current-build browser/auth evidence belong to the independent acceptance lane.

Run from an isolated checkout using the retained dependency cache:

- `node tests/technology-final-two-20261111/native.postgres.mjs`
- `node tests/technology-final-two-20261111/sharing.postgres.mjs`

Normal execution independently reconstructs and verifies the committed SQL bytes. The explicit `--capture` authoring mode writes only this new package; never use it against retained historical packages. Every SQL file retains an unconditional UNAPPLIED guard. Local fixture tests remove only the named guard in memory. RELEASE HOLD remains active.
