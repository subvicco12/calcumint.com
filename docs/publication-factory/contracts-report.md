# Exact private contract input preparation

The offline cohort contains 76 existing private candidates: 25 `private.component` v1 and 51 `private.remaining` v1. Membership starts with the explicit existing batch16 immutable-workflow group and joins each identity to its exact readiness private candidate, immutable version and individual vector evidence. The three calculus v3 identities in that group are explicitly excluded because readiness does not record matching private candidates. A missing binding for any other member refuses selection.

`parsePublicationFactoryInput(text)` is a new-input boundary. It preserves ordinary malformed-JSON `SyntaxError`, limits text to 2,000,000 characters and nesting to 128, ignores quoted string contents, and refuses numeric tokens whose normalized decimal spelling changes through Number/string conversion. Nonzero underflow and nonfinite overflow are refused. Equivalent spellings such as `1.00`, `1e3`, and stable finite values such as `0.1`, `1e100`, and `9007199254740992` are accepted. Integer and domain bounds remain the actual selected schema's responsibility. This detects decimal spelling loss; it does not claim exact binary decimal arithmetic or full-domain numerical acceptance.

`parsePublicationFactoryNumber(text)` returns a Number only for stable decimal form spelling and retains invalid, incomplete or lossy text as a string for form/schema feedback. Precision refusals are ordinary Error objects with a precision message; malformed JSON retains native SyntaxError. No historical import, replay, source binding, engine version or saved artifact is changed.

`contracts-evidence.json` records actual execution of 152 pre-existing witnesses for 76 exact adapters. Each uses its original golden comparison, including the existing scaled absolute tolerance where declared. All three plan artifacts are identical for each witness, and the original serialized artifact replays unchanged. This is bounded software evidence, not new independent mathematical witnesses, family acceptance, authenticated persistence, certification or publication authorization.

Native decimal forms `.5`, `+1`, `1.`, `01`, and `-.5` remain accepted by the form helper; hexadecimal and incomplete drafts remain raw strings. Advanced JSON retains strict native JSON syntax.
