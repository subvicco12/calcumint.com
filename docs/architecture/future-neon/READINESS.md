# Future Neon compatibility — design only, transition deferred

Owner direction21 October2026: retain existing Supabase interfaces for development. No resources, connection changes, migration/data transfer or rollout are authorized. This inventory informs a separately approved transition, not a new runtime abstraction.

| Boundary | Current application evidence | Future dependency/acceptance |
|---|---|---|
| Auth/session | src/lib/supabase/browser.ts,server.ts,session-cookies.ts,session-bound-fetch.ts; PKCE/recovery/account-bound requests | Select identity provider/session authority explicitly. Neon PostgreSQL does not replace Supabase Auth. Preserve UUID identity, expiry, revocation contract, secure cookies, PKCE and historical owners. |
| PostgREST data transport | Pages/actions use scoped .from queries and .rpc through existing Supabase clients | Choose compatible gateway or server data adapter, with error/cursor/count semantics and current fail-closed missing-RPC behavior. Do not replace a REST URL with a SQL endpoint or expose database credentials in browser code. |
| RLS/JWT roles | auth.uid/role/jwt helpers, anon/authenticated/service_role, SECURITY DEFINER owners/grants | Verified JWT claims must be set by trusted server/gateway per transaction. Pooled connections must not retain prior-account claims; test owner switching, transaction rollback and denied inherited privileges. |
| Atomic RPCs | src/lib/account-persistence.ts, billing atomic-webhook, API batch/embed services and unapplied guarded proposals | Preserve PostgreSQL transaction/fence/receipt/quota semantics, exact overloads/body versions/ownership, advisory/profile/key locks, retries and rollback. Compatibility requires separate reviewed SQL adoption, not name/signature matching. |
| Privileged server operations | src/lib/supabase/admin.ts and trusted webhook/API services | Inventory all writers; explicitly preserve service privileges and signature verification while denying browser/public/internal execution paths. New provider credentials require separate authorization and secret handling. |
| Storage/Realtime | No direct .storage/.channel/postgres_changes usage found in bounded src search | This is not proof of absence in external workers or future requirements. Inventory external integrations before transition; do not silently replace or activate services. |
| Schema/platform | Captured public schema references auth.users, extension/helper/role contracts; identity sequences/platform settings remain bounded fixture dependencies | Identity/FK bridge, extensions, sequences/options/state, grants/default ACLs, backup/restore, migration history and operational evidence need separately approved decisions. Preserve all immutable history, Slope v1, SIP v1 and publication authority. |

Proposed future checkpoints: (1) explicit transition scope/provider/writer inventory; (2) compatible local gateway/claims adapter contract tests; (3) disposable target schema/role/RPC and cross-account concurrency parity; (4) separately authorized backup/data reconciliation/transition/rollback. No checkpoint is approved or executed by this application batch. Existing abstractions remain unchanged because an unused speculative adapter would not resolve a verified defect.
