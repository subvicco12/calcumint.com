# Source-bound correction and reversal bundles

Engineering authorization only; no production adoption. `tests/owner-p0/adoption/plan.json` pins nine reviewed source files:009,032–035, the narrowed caller ACL candidate, and date/final-row/P0 publication successors. It separately pins the membership apply/reversal sources. No historical SQL or active migration changes.

The offline builder accepts only explicitly labelled isolated snapshots and emits SQL with an unconditional abort guard inside one transaction. There is no production connector or activation switch. Test code removes that guard only in memory. Source SHA-256, PostgreSQL17, missing new target names/overloads, original predicate owner/definition and exact declared metadata fingerprints prevent silent overwrite or incompatible composition. Constituent preconditions remain; only their transaction wrappers and unconditional guards are composed under the outer guard.

Thirteen genuine isolated PostgreSQL17.6/GoTrue/PostgREST checks exercise default refusal (also with SQL-client error continuation), unsupported snapshot isolation, schema drift, late all-or-nothing failure, combined account/admin/publication installation, strict reapplication refusal, membership coexistence and reversal, country-data protection, both country-write/rollback commit orders, full semantic metadata restoration, and deliberate reinstall.

The fixture combines fourteen public tables with local provider auth. The metadata projection includes declared public relations/columns, function definitions/owners/ACLs, indexes/constraints/triggers/policies and auth relation/function control metadata. It excludes application/auth rows and is not whole production-schema or data equivalence. Provider control projection remains unchanged. Completed member/audit rows and preexisting profile/preferences rows survive reversal.

Reversal is separately guarded, bound to the postimage, restricted to exact introduced function signatures and trigger/table pairs, and never uses CASCADE. Unknown objects/overloads or unexpected changed existing functions refuse generation. Only exact original client ACLs are restored; unrelated provider/service controls remain. Country values must be NULL before removing the added country column. An ACCESS EXCLUSIVE table lock is taken before checking metadata/data and retained through removal, under READ COMMITTED. The tests prove that earlier country writes force refusal and later writers cannot commit into the disappearing column. No tool automatically clears user data.

PostgreSQL does not reuse dropped attribute numbers. After reversal/reinstall, the visible country column has a new internal ordinal and therefore a new strict postimage hash. Tests explicitly verify that this is the sole difference and every other declared semantic field is identical; future reversal must bind that fresh postimage. This is not physical file/catalog rollback.

Restoring known-defective predecessors is **technical reversibility proof only**, never an approved safe production rollback. Critical workflows must be held and an independently reviewed recovery plan, fresh target/data audit, participating-writer boundary and separate rollout/rollback authority remain required. Operator DDL concurrency requires quiescence/coordination beyond these tested data-writer schedules. No hash or fixture label authenticates a production target.

Artifacts are generated outside Git using `ADOPTION_ARTIFACTS`; final apply/reversal SQL and receipts are bound in validation.json. All generated and checked-in successors remain guarded. RELEASE HOLD remains active.
