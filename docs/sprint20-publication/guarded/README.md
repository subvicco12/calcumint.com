# Guarded draft inventory provisioning

This proposal corrects the bulk admin path's independently committed catalog/QA writes, absent creation audits, and attempts to UPDATE jobs under RLS without an UPDATE policy. It adds no publication authority and changes no RLS policy.

`prepare_catalog_inventory_drafts.sql` remains outside active migrations and starts a transaction before its unconditional activation exception. Do not remove the exception for a hosted deployment without explicit activation authorization and exact environment review. A failed guard aborts the transaction even when a SQL client continues after errors. Installation also requires every public function named `prepare_catalog_inventory_drafts` to be absent, and uses CREATE without OR REPLACE. An unexpected existing definition or installation replay is explicitly rejected without replacing that definition; runtime RPC retries remain idempotent.

The invoker RPC accepts 1–250 objects with exactly `calculator_key`, `slug`, `title`, `category`, `risk_class`, `metadata`, and numeric `version: 1`. Only active owners/admins may call it. The app must first resolve exact registered identity, engine version and risk, and construct registry regulatory metadata. Optional `metadata.engineBinding` is accepted. Existing nonempty bindings must match; legacy absent bindings are preserved. This RPC does not independently contain or certify the application registry.

Both key/slug advisory locks are acquired in global sorted order before actual existing-row locks. Missing rows call the existing atomic creation RPC. Compatible drafts receive only missing pending QA checks; existing QA decisions and audit events remain unchanged. Compatible nondrafts are read and preserved. Key/slug/title/category/risk/version/rule-pack conflicts abort the entire batch. A completed job is inserted only at the end of the same transaction. Retries may create a new completed attempt job, but never duplicate a creation audit. There is no job UPDATE policy, service-role fallback, or lifecycle transition.

Activation dependencies: reviewed source/schema capture from the target; predecessor function definition SHA-256 exactly `d2d7a27c14c06c02b8682a7ab755bbd64612044780c500db5bfe5b7267bbd28b`; original migration source SHA-256 `426de9383b1ca63f504adbdb9e515c239c8d2c4bd37f518a6b900667d2f30b47`; required RLS tables and database version-one default; applicable existing QA constraints, invoker table/sequence privileges and triggers; explicit operator authorization; PostgREST schema cache reload. Deploying app callers before the RPC exists fails closed and requires the guarded dependency to become available. This does not approve activation.
