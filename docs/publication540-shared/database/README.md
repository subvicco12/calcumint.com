# Held isolated batch publication mechanism

This prototype closes a narrowly demonstrated orchestration gap; it grants no activation or publication authority. All SQL entrypoints deliberately fail before DDL. They are not active migrations. `guarded-target-apply.sql` and `guarded-target-reverse.sql` form the independently executable, exact reversible held addon package; the smaller constituent files document its source. No production execution was performed.

The existing `transition_calculator_with_audit(uuid,text,text)` in `docs/adoption1528/package/guarded-target-apply.sql:133` compares UUID and lifecycle, then writes its audit. It does not compare immutable version, identity, contract metadata, QA or sources. `docs/adoption1528/REPORT.md:36` explicitly leaves exact version/contract/source/QA orchestration outside that package. Independent successful RPC calls can commit a prefix of a release batch. Existing single-item audit atomicity remains correct.

`publish_calculator_batch_with_audit_v1(p_items jsonb)` returns the count. Each item requires `id`, `calculator_key`, `slug`, `version`, `expected_catalog`, `expected_metadata`, `expected_sources`, `expected_qa`. `expected_catalog` is the exact persisted `to_jsonb(calculator_catalog_admin)` row, metadata is its exact JSON object, and the two evidence arrays contain complete persisted rows sorted by UUID `id`. This deliberately rejects even benign timestamp drift, requiring a refreshed offline plan. The immutable engine implementation/contract hash must also be independently verified by the offline release verifier; PostgreSQL cannot establish repository implementation identity from a caller assertion.

Only certified → published is supported. The successor cannot assign reviewers, synthesize QA, create evidence, certify a row or choose an arbitrary target. It calls the predecessor audited transition and existing authoritative gate without replacing either. It adds no tables, table grants, policies or security-definer authority. It requires an active owner/admin under `authenticated`; service_role has no function EXECUTE. The 1–100 count is an implementation resource bound, not an entitlement or publication policy.

The gate reads catalog metadata/rule packs, QA, source evidence, reviewer assignment and active platform reviewer capability. Under READ COMMITTED, SHARE ROW EXCLUSIVE locks on QA, source evidence and platform admins precede catalog row locks in UUID order. Evidence/authority table locks serialize these prototype batch callers and prevent snapshot races with source/QA insertions and reviewer revocation. The existing source AFTER trigger updates its parent, so parent locking alone would not establish the complete evidence snapshot precondition. Independent writers taking locks in different orders can deadlock; PostgreSQL aborts a participant and callers must retry the whole transaction. Operator lock/statement timeouts and independent DDL quiescence remain required. No claim covers privileged writers that disable triggers, ignore transactional locking or later mutate committed rows.

`tests/publication540-shared/database.mjs` reconstructs all seven captured hosted-shaped tables, policies, ACLs, functions and triggers using the existing adoption initializer and source-bound guarded composition. Only synthetic local rows and explicitly synthetic passing evidence exercise positive transactions. Genuine GoTrue JWTs exercise role denials and allowed owner invocation. The receipt lists observed checks. Successful reversal only removes the added function, preserves data/audits and restores the predecessor scoped metadata; it does not undo already committed lifecycle transitions.

The addon wrapper hashes the complete existing adoption catalog projection plus every overload of the new function, including exact definitions, owners and ACLs. It rejects an existing addon name, incompatible metadata, replay, changed predecessor/provider/RLS/ACL/default privileges, and drifted reverse postimages. The preimage uses the existing derived adoption1528 expected postimage; the successor postimage is derived in the disposable fixture and transplanted onto that unchanged captured base. This is a source-bound derived target package, not a fresh observation of production. Operator postgres, READ COMMITTED, bounded table locks, unconditional transaction hold, and pre/postcondition checks apply in both directions. `source-bindings.json` pins all inherited constituent files and the local package builder. Fresh target observation, DDL quiescence, participating writer reconciliation and separate activation/recovery authorization remain external blockers; the hold remains unconditional. The existing adoption package is unchanged.
