# Reusable contract evidence infrastructure

The original Blueprint supplies architecture, not a complete mathematical contract for every catalog row. This work adds reusable verification of established private contracts and exact per-ID evidence. It does not grant canonical mappings, certification, publication or qualified applicability.

## Approach

Reuse immutable engines through adapters with explicit input/output schemas, actual-artifact identity projection, original methodology and replay readers. A single evaluator executes authored numerical witnesses, strict unknown-field rejection, domain negatives, all-plan equality, exact version/identity matching, deterministic replay and version/output tamper rejection. Expected values are constants with derivations, reused from prior independent methodology evidence, never collected from the engine under test.

Alternatives considered were another calculator-specific test layer or automatic canonical promotion from registry presence. The shared adapter approach makes validation reusable while retaining exact original technical versions and scope. Registry presence cannot establish canonical acceptance. Existing TypeScript, Zod, shared result renderer and private authenticated loopback fixture are reused; no dependency, provider, production database or engine change is needed. These are engineering choices within the owner's execution direction.

## Initial coverage

28 adapters cover fixed monthly loans, requested debt payoff, caller-selected affordability, debt/income ratios, fixed-budget strategies, refinance, supplied down payment, named mass conversion, inherited approximate US volume conversion, and calculus revision3. Fifty-six independently specified witnesses and 28 negative cases exercise actual engines. The volume contract preserves approximate inherited factors; it does not infer exact regional equivalencies or ingredient density.

Every report names its adapter, related catalog ID, exact engine revision, checks and scope. A relabelled adapter must fail against identity fields extracted from the actual artifact. Golden comparison requires exact JSON primitive equality, explicitly checks expected property presence and array lengths, and has no hidden tolerance. Original engine rounding is checked at the authored witnesses; this is not exhaustive proof of the entire rounding/domain specification.

The offline source binder captures first-party calculator sources, immutable snapshot code, lockfile, native Blueprint/trace and literal imported JSON dependencies. Its own binding JSON is the sole declared self-reference exclusion. This is local technical provenance, not authenticated publisher bytes or applicability approval. The emitted source hash is not a cryptographic authorship signature.

## Workflows and evidence

A private review tool can run schema-validated JSON input, inspect full original output and methodology, execute fixed witnesses, preserve same-browser review history, compare complete same-contract scenarios and export immutable validation packets. Central entitlements control professional workflows and new history writes; mathematical artifacts remain identical across plans. Corrupt/unsupported history blocks new writes and retains original storage bytes. This tool does not replace the complete calculator UI or authenticated account history.

The 540-row manifest preserves every prior classification and authority blocker. Selected requirements are marked satisfied only for recorded private witnesses. Source/applicability, complete domain, account persistence and canonical scope remain partial or blocked. Unselected identities retain prior evidence references and are not silently marked missing or complete. All 497 reviews and 43 authority blocks remain active.

Mandatory CI checks verify source hashes and exact generated evidence, in addition to unit/browser and unchanged security/publication guards. No historical engine, existing export reader, 424-record ledger or original DRAFT changes. RELEASE HOLD remains active.

Future validation revisions must preserve shipped packets and their reader/source bindings rather than regenerating old receipts. Unsupported source/revision history blocks writes and retains raw storage; broader cross-revision account adoption remains partial.
