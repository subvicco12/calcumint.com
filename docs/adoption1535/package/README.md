# Review-only composed adoption package

Run `node scripts/adoption1535/package.mjs --check` for an offline source-pin and generated-byte check. Run `node scripts/adoption1535/package.mjs --rehearse` for a new disposable pinned PostgreSQL 17.6 / GoTrue / PostgREST fixture. The rehearsal rejects the explicit target selectors DATABASE_URL, SUPABASE_DB_URL, PGHOST, PGSERVICE and PGDATABASE, accepts no connection arguments, and hardcodes its disposable Docker fixture; no operator connection is used. There is no activation flag or production executor.

`guarded-target-apply.sql` composes the immutable adoption1528 core and publication540 atomic batch addon in a single transaction. `guarded-target-reverse.sql` reverses addon then core in one transaction. Each retains every constituent operator, READ COMMITTED isolation, bounded lock, complete metadata precondition and postcondition. Both contain one unconditional outer transaction hold. A continuing client cannot commit past that hold. The core projection includes every overload of named RPCs, table/column ACLs, RLS policies, provider definitions/ACLs and default function ACLs. The addon projection includes every overload of the atomic batch RPC. Source hashes bind the constituent SQL and its transitive provenance.

These files perform schema-only operations: no data-changing statement executes outside function definitions, and reversal uses no CASCADE. Either complete transition commits or the transaction rolls back, including an addon failure after core installation or a core reverse failure after addon removal. An interrupted transaction requires rollback/disconnection, followed by a fresh read-only exact metadata capture. Retry only against the complete expected starting image; a partial image or any drift is a hard refusal. Successful reversal restores known-defective predecessors, so workflows must stay held until separately authorized recovery. Reapplication uses the same held complete apply package.

The generated target files retain the historical exact captured core preimage and derived successor postimages; they do not assert that any derived state has been observed in production. No migration, approval, certification, merge, deployment or publication is authorized by this package. The parent operator runbook must reconcile the fresh target capture with these pinned projections before any separately approved adoption.

The focused rehearsal also installs the two exact read-only captured `extensions.pgrst_ddl_watch` and `extensions.pgrst_drop_watch` bodies and matching enabled event triggers before core installation. Their SHA256 values and both evidence files are pinned. It confirms a cold PostgREST cache has no addon, aborted composition exposes no addon, and committed composition discovers the atomic RPC using a genuine owner JWT through automatic transactional provider `NOTIFY`, with the legacy runtime helper's manual reload suppressed. Every metadata checkpoint also verifies the local callback definitions, owners, ACLs and event registrations remain unchanged through application, rollback, reversal and recovery.

This is a source-reference boundary, not a reconstruction of the provider: the local `supabase_admin` role is explicitly created as SUPERUSER to own the captured event triggers; hosted role attributes and privileges are not inferred. The four other captured provider hooks are scoped exclusively to CREATE/DROP EXTENSION; this package asserts it contains no such operation and does not install or invoke those callbacks in the fixture. The captured callback bodies are not added to target SQL, and the additional fixture evidence does not expand activation authority.
