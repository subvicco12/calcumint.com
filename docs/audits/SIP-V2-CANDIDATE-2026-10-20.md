## Compatibility recommendation

A new version and fresh certification are required. The existing 55 exact decimal-reference cases identify 25 v1 differences; the prior 750-case grid identified 256 differences. Those diagnostic populations have different purposes and must not be conflated or silently rebound to v1. The candidate tests consume the 55 independent vectors: representable currency results agree with exact rational cents; excessive currency results intentionally reject. These checks do not certify the 750-grid population or establish specialist approval.

The authored formula remains `PMT × ((1+r)^n−1)/r × timingFactor`, with `r = annualReturnPercent/1200`, timing factor `1+r` for beginning deposits and `1` for end deposits, and the exact zero-rate limit `PMT×n`. The algebraically equivalent monthly recurrence evaluates that single formula for every plan and context. No epsilon replaces a nonzero rate. Unlike cancellation-prone powers, ±1e-12 at PMT 10000 and n=1200 return **12000000.00**, for either timing.

## Proposed bounded decimal policy and proof

Inputs are the exact canonical decimal strings produced by `Number.toString()`, matching the existing independent rational oracle's source contract. This differs from treating binary64 bit patterns as exact financial decimal inputs. Every finite binary64 canonical decimal fits the internal scale `S=10^360`: even subnormal minimum exponent −324 fits exactly. Input schema keeps positive PMT, annual rate [−99,1000], integer months [1,1200], and default beginning timing. Direct forward helper additionally permits zero PMT, but validates all other arguments. Candidate calculate validates direct calls itself. Invalid inverse arguments throw, rather than v1's historical sentinel behavior.

Internal amounts use integers scaled by S. Let q=1+annual/1200. It is positive throughout the supported domain. Compute `qLo=floor(Sq)` and `qHi=ceil(Sq)`. Starting from `[0,0]`, each deposit maps the bounds to `[floor(lo*qLo/S)+PMT*S, ceil(hi*qHi/S)+PMT*S]`. Beginning timing applies one extra outward-rounded multiplication. Positivity and monotonicity prove by induction that every interval encloses the exact decimal recurrence. There is no accumulated binary64 error in these integer operations. The loop is bounded at 1200, and operands remain bounded by finite binary64 input magnitude plus the bounded accumulation exponent.

Round both interval endpoints to nearest cent with positive ties up. Equal endpoint cents certify the exact result. If the interval straddles a rounding boundary, a separate exact rational geometric-sum fallback resolves ordinary exact ties, including PMT241.2, annual5, n1, beginning: **242.205 → 242.21**. The fallback reduces the rational rate and principal and constructs exact integer powers; it rejects before exponentiation when `max(decimalDigits(q),decimalDigits(d))*n > 20000`. This is a deterministic work cap, not a numerical epsilon. An ambiguous case exceeding this cap fails closed with a precision error; universal acceptance of all schema-valid inputs is not claimed.

The rounding policy remains a draft requiring review. Invested amount rounds independently in exact decimal cents; estimated gain subtracts those two rounded integer-cent amounts. The unrounded forward helper returns an approximate binary64 midpoint only after certifying its rounded cents. Inverse uses the same unrounded accumulation factor, validates the resulting forward amount, and returns an approximate binary64 contribution; it does not promise exact display reconciliation for arbitrary inverse targets.

## Currency limits

No enormous-currency exact-cent guarantee is made. Each output's integer cents must be within `Number.MAX_SAFE_INTEGER`, **and** converting cents to a number of currency units must round-trip through its canonical decimal string to the exact same cents. Future value, invested amount, and signed gain are each checked. The second check is essential: exact cents 9007199254740951 are below the safe-integer ceiling, but division by 100 serializes as 90071992547409.52. PMT30023997515803.17, n3, rate0 therefore rejects. A number is still an approximate binary64 representation; the check guarantees canonical decimal serialization of accepted rounded outputs, not exact binary representation of cents.

Huge finite inputs (1e100, 1e300, 1e308) and finite but excessive high-return results reject rather than return misleading cents or Infinity. The interval evaluation itself remains bounded; this is an intentional proposed restriction beyond the historical v1 input schema. Unknown specialist approval and unresolved product policy for explaining these errors remain release blockers.

## Independent evidence

Formula references: [OpenStax Contemporary Mathematics §6.3 Annuities](https://openstax.org/books/contemporary-mathematics/pages/6-3-annuities) and [Investor.gov compound-interest calculator](https://www.investor.gov/financial-tools-calculators/calculators/compound-interest-calculator). Annual nominal-rate conversion, timing convention and rounding policy are explicit calculator contract choices; references do not constitute approval of the implementation.

`verification/sip-high-precision-reference.ts` is an independent exact rational deposit recurrence, imported only by tests. Its 55 vectors cover zero, ±1e-12, ±1e-10, −99, 10, 1000, both timings, months1/2/1200, half-cent neighbors, and enormous finite currency. Five candidate-only literal goldens were independently reproduced using Python decimal at 200-digit precision, deposit recurrence and ROUND_HALF_UP; the literal ordinary 10-year example remains 2065520.20. Four independently derived negative-return inverse vectors also pass.

For ±1e-300 the existing oracle deliberately cannot parse the exponent. Independent analytic reasoning supplies the limit check: for PMT10000, n1200, |r|=1e-300/1200, each power differs from 1 by at most `1201|r|exp(1201|r|)`; summing 1200 deposits bounds the total deviation below 1e-289 currency units, vastly below half a cent. Both signs/timings therefore round to 12000000.00. To ensure this is not an epsilon substitution, PMT0.005,n1,beginning tests positive tiny rate →0.01, negative tiny rate →0.00, exact zero →0.01.

74 candidate tests cover those vectors, invalid schema/direct calls, recurring exact ties, independent inverse cases, contexts/plans, currency round-trip rejection and runtime measurement. Local benchmark: 100 evaluations at n1200, alternating annual−99 and1e-300, **327.1ms total (~3.27ms each)** on this workspace. This is an observation, not a latency SLA or billing claim; no timing threshold is asserted. Exact-boundary fallback performance has bounded work but has not been characterized across all allowed operands.
