# SIP v2 draft projection adapters — 2026-10-20

Release hold: unregistered draft version 2. No certification, production registration, publication, deployment, history migration, shared precision changes or v1 behavior changes.

The new `final-framework/sip-v2-projection.ts` directly imports only the v2 candidate. `buildSipV2DraftProjection(rawInput, context?)` returns identity `{id: 'finance.sip', slug: 'sip-calculator', version: 2}`, draft review status, validated/defaulted input, authoritative candidate output, exact caller-supplied optional locale/currency context, a structured renderer result, and `periodStatus: 'available' | 'unavailable'`. Currency is only a caller-authored unit; no locale/currency inference or conversion occurs.

The additive `sipV2PeriodSnapshots(raw)` helper uses one decimal interval recurrence for all monthly prefixes. The arithmetic state remains unrounded; each snapshot applies the same rounding, safe-cent round-trip checks and bounded exact fallback as candidate calculation. Cumulative contributions, modeled gain and future value are snapshots, not cash-flow transactions. Existing aggregate/inverse/forward helpers are unchanged. Rare fallback work remains bounded by the candidate's 20,000-digit guard.

A valid terminal result may have a prefix that cannot round-trip decimal cents. Example: contribution 11000000000000.01, zero return, eight end-of-month deposits gives valid terminal 88000000000000.08 while an intermediate prefix fails precision checks. Such optional projection failure retains the valid core result, explicitly marks periods unavailable, discloses the reason, and omits all chart/schedule rows rather than fabricating data.

`serializeSipV2DraftJson` and `serializeSipV2DraftCsv` validate the complete payload against the direct v2 builder, including identity, input, output, status, context, chart, metadata and rows. They reject stale/tampered payloads and invalid JSON values. JSON preserves explicit negative zero numeric input. CSV quotes all fields, identifies version/draft/context, includes aggregate output/status, and serializes exactly the validated renderer rows. Serializers do not invoke v1, registry or history. They recompute v2 validation and do not authenticate the origin of a self-consistent payload.
